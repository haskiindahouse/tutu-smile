# Улыбка (tutu-smile)

Сервис собирает гостей события из разных городов к одному дедлайну: организатор задаёт рамки — «Улыбка» строит каждому маршрут, держит живое табло прибытий и выдаёт гостям ссылки «дожать» на чекаут Туту. Бесплатно; воронка в чекаут Туту.

Хакатон ИИ × Туту MCP.

MCP: `https://mcp.tutu.ru/mcp` (JSON-RPC, без авторизации).

## Запуск

Один бинарник на Go 1.26 — бэкенд оркестрирует MCP и раздаёт фронт.

```bash
cp .env.example .env      # заполнить OPENROUTER_API_KEY и MAPBOX_TOKEN (оба опциональны)
go run ./cmd/smile        # http://localhost:8080
go test ./...             # юнит-тесты: планировщик, волна, MCP-клиент, парсер
```

Секреты только в `.env` (в git не коммитится). Без ключа OpenRouter умный ввод
выключен с понятной подсказкой, вайб-режим и человеческие карточки деградируют к
детерминированным заготовкам; без Mapbox-токена скрывается карта. Всё остальное
работает на живом MCP без ключей.

## Что умеет

- **Умный ввод**: одно поле — напечатать, надиктовать голосом (Web Speech API)
  или вставить переписку из чата; черновик парсится живьём по мере набора
  (чипы-предпросмотр), полный черновик уходит сразу на табло минуя конструктор.
  Правки тоже текстом: «добавь Пашу из Перми» — черновик мёржится.
- **Join-ссылка «отметься сам»**: организатор не вводит гостей — одна ссылка
  в чат, каждый гость вписывает себя за пять секунд (город, профиль, ночлег,
  попутчики) и попадает на живое табло у всех. Ввод данных распределяется по
  группе — это и делает инструмент групповым.
- **Событием управляют словами прямо на табло**: «перенеси сбор на 16:00,
  добавь Свету из Уфы с ночёвкой» — печатью или голосом; merge без удалений
  (убрать гостя можно только явным действием).
- **Мгновенное добавление без LLM**: строка «Паша из Перми, быстрее, с
  ночёвкой» разбирается на клиенте; города автодополняются из гео-индекса.
- **«Увидеться вдвоём»**: повод не нужен — два города, и живые цены Туту
  считают, где встретиться дешевле всего обоим («Киров: тебе самолёт 4717₽,
  другу поезд 2830₽ — встреча за 7547₽»). Один клик — и город встречи
  становится событием с табло и чекаутами. Индустрия продаёт «куда поехать»,
  «Улыбка» считает «где встретиться».
- **Цена улыбки**: табло показывает, во сколько обходится один обнятый гость
  (дорога всех ÷ гостей); когда собраны все — дождь из 🙂.
- **🎰 Рулетка «куда ехать»**: лекарство от паралича выбора. Плитки интересов
  (рыбалка, купаться, покушать, природа, горы, история, тусовки, отдых, спа) +
  бюджет + даты + РФ/заграница → живые ПОЛНЫЕ цены поездок (туда + обратно +
  отель на все ночи) по подходящим городам → барабан крутится и выбрасывает
  город с чекаутами на всё. «Крутить ещё» переигрывает по уже полученным
  вариантам без новых вызовов. Плитки интересов сужают и «Увидеться вдвоём».
- **🗺 Маршрут по городу → Google Карты**: ИИ собирает пеший план по дням под
  интересы (реальные известные места), каждый день открывается одной ссылкой
  в Google Maps как walking-маршрут с waypoints. Честно помечено «сгенерировано
  ИИ» — часы и дороги проверяет Google.
- **Маршрут от дедлайна назад** каждому гостю: мультитранспорт + ночные поезда
  прошлой датой + пересадочные планы, ранжирование по профилю (дешевле/быстрее)
  и бюджету.
- **Живое табло**: SSE-поток, перепроверка живого инвентаря по расписанию,
  честный диф «рассыпался → пересобран», лог решений по каждой строке.
- **Карточка гостя = продукт**: гость сам выбирает вариант (пин переживает
  перепроверки, пока вариант жив в продаже), отмечает «я купил» (строка
  замораживается), даёт согласие на раскрытие имени попутчику.
- **Волна обнимашек**: прибытия с зазором ≥N минут; закреплённые и купленные
  маршруты волна не трогает; гости в одном вагоне — одно прибытие.
- **Попутчики (opt-in)** + **места рядом**: живой seatmap РЖД
  (`get_rail_seatmap task=together`) называет вагон и соседние места с ценой.
  Приватность: имена открываются только при взаимном согласии.
- **Отели для ночующих** (ТЗ §8): `search_hotels` у места события, цена за весь
  стей, тот же чекаут-чейн.
- **Тотализатор**: честная вероятность опоздания из хрупкости маршрута
  (пересадки, ночной перегон, запас); у купленных билетов шансы падают.
- **Вайб-режим**: «хотим к морю, недорого» → LLM предлагает города-кандидаты,
  живые цены Туту ранжируют их по полной стоимости сбора всех гостей.
- Приглашение гостю в один клик (готовый текст со ссылкой), экспорт сбора в
  календарь (.ics).

## Архитектура

```
cmd/smile            точка входа, сборка зависимостей
internal/mcp         JSON-RPC клиент к Tutu MCP: TTL-кэш, ретраи, single-flight,
                     politeness-gate (конкурентность+зазор) и circuit breaker
internal/tutu        типизированный домен над MCP: поиски, отели, seatmap
                     («места рядом»), checkout_ref → deeplink, гео
internal/planner     маршрут «от дедлайна назад»: ночные поезда, пересадки,
                     ранг по профилю, пин выбора гостя
internal/wave        «волна обнимашек» — раскладка прибытий с зазором;
                     замороженные строки не трогает
internal/companions  пересечение сегментов opt-in гостей; имена — только при
                     взаимном согласии
internal/orchestrator фан-аут по гостям, диф «рассыпался → пересобран»,
                     заморозка купленных, отели, seat-hints, тотализатор,
                     вайб-ранг, планировщик перепроверок
internal/event       модель события/гостя/табло, in-memory стор + SSE-подписка
internal/llm         OpenRouter с цепочкой fallback-моделей: текст/голос/чат →
                     черновик события; вайб → города; маршрут → человеческая фраза
internal/api         REST + SSE + ICS, раздача фронта
web/assets           SPA: умный ввод с голосом, живое табло, карта Mapbox,
                     волна, карточка гостя с самообслуживанием
```

**Бережливость к MCP — фича корректности.** Живой прогон показал: неограниченный
фан-аут ловит TLS-бан WAF'а. Поэтому клиент держит потолок одновременных
запросов и зазор между ними, а серия сетевых отказов открывает circuit breaker:
вызовы падают быстро, перепроверки пропускаются, табло держит последнее честное
состояние (сбой сети ≠ «маршрут рассыпался»), шапка показывает «Туту остывает».

**Где работает ИИ (и зачем):** (1) умный ввод — свободный текст/диктовка/чат →
структурный черновик события, организатор только подтверждает; (2) вайб-режим —
LLM предлагает города, живые цены Туту ранжируют (LLM не решает); (3)
человеческая карточка гостя — перевод маршрута в одну тёплую фразу. Все три
места деградируют без ключа, продукт остаётся рабочим.

**Полный чейн до Туту:** `search_multitransport`/`search_rail`/`search_hotels` →
`checkout_ref` → `create_checkout_link` → deeplink «дожать». Ссылка передаётся
байт-в-байт, не пересобирается. Seatmap читается по `details_ref` тем же чейном.
